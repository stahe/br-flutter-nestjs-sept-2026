    1. Visual Studio Code (VSCode): disponível para download gratuito em code.visualstudio.com. Instale a extensão “TypeScript and JavaScript Language Features” (geralmente já incluída).
    1. [MySQL] 8: instale, por exemplo, por meio do XAMPP, do Laragon (no Windows) ou diretamente pelo [MySQL] Community Server. Uma ferramenta gráfica de administração (phpMyAdmin, [MySQL] Workbench, DBeaver, HeidiSQL…) facilita o trabalho. A seguir, será usada a ferramenta Laragon.
    2. Postman: disponível para download gratuito em postman.com.

    2.1.2. Android Studio e ferramentas de linha de comando do Android

    O destino mobile deste curso é um celular [Android]. Para compilar a aplicação e instalá-la nesse celular, o [Flutter] precisa do SDK do [Android], que é instalado junto com o [Android Studio], o ambiente de desenvolvimento do Google. O [Android Studio] não é usado para escrever código (o editor continua sendo o [VSCode]); aqui ele serve apenas para instalar e atualizar o SDK do [Android].

    1. [Android Studio]: baixe-o gratuitamente em [https://developer.android.com/studio] e instale-o. Ao iniciá-lo pela primeira vez, o assistente oferecerá uma instalação padrão: aceite-a, e ele baixará o SDK do [Android].

    1. Abra o [SDK Manager] a partir do [Android Studio] (menu [Tools / SDK Manager] quando um projeto está aberto, ou [More Actions / SDK Manager] na tela inicial): essa é a ferramenta que instala e atualiza os componentes do SDK do [Android].
    2. Aba [SDK Platforms]: verifique se uma plataforma [Android] recente está instalada (a documentação do [Flutter] especifica a versão 36 no momento da redação).

    1. Aba [SDK Tools]: marque [Android SDK Command-line Tools (latest)], [Android SDK Build-Tools] e [Android SDK Platform-Tools] (assim como o [Android Emulator] se quiser testar em um emulador) e clique em [Apply]. A documentação do [Flutter] também recomenda o [CMake] e o [NDK (Side by side)]. São os pacotes do [Android SDK Command-line Tools] que estão faltando quando o [flutter doctor] exibe “cmdline-tools component is missing”.
    2. Aceite as licenças do SDK do [Android] digitando o comando a seguir em um terminal dentro do projeto Flutter e respondendo “[y]” a cada pergunta, até ver a mensagem “All SDK package licenses accepted.”: 
      3
      flutter doctor --android-licenses

    [Nota]: Com a versão 23.0 do [Android SDK Command-line Tools], o comando acima pode terminar imediatamente, sem perguntar nada, exibindo “The --licenses option is no longer needed.” Trata-se de um problema conhecido do [Flutter] (issues 191558 e 191487 em github.com/flutter/flutter). Solução alternativa: no [SDK Manager], aba [SDK Tools], marque [Show Package Details], substitua a versão 23.0 do [Android SDK Command-line Tools] pela versão 22.0, clique em [Apply], e então execute o comando novamente.

    2.1.3. Criar um emulador Android

    Se você não tem um celular, pode testar a aplicação em um emulador [Android]: um celular virtual que roda em uma janela do seu computador. O [Android Studio] instala o programa [Android Emulator] (se ele foi marcado no [SDK Manager], veja acima), mas não fornece um dispositivo virtual pronto para uso: é preciso criar um.

    1. [Pré-requisito]: a virtualização deve estar habilitada na [BIOS] do computador e, no [Windows], o recurso [Windows Hypervisor Platform] deve estar marcado ([Control Panel / Programs / Turn Windows features on or off]), o que exige uma reinicialização. Caso contrário, o emulador não iniciará ou ficará muito lento.
    2. Abra o [Device Manager] a partir do [Android Studio]: [More Actions / Virtual Device Manager] na tela inicial ou [Tools / Device Manager] quando um projeto está aberto (dependendo da versão: [View / Tool Windows / Device Manager]).

    1. Clique em [Create Device], selecione um modelo (por exemplo, [Pixel 8]) e depois [Next]. Selecione uma imagem de sistema [Android] recente para o processador [x86_64] e baixe-a usando o link [Download] ao lado dela; em seguida, clique em [Next] e em [Finish].

    1. Inicie o emulador pelo botão [Play] do [Device Manager] ou a partir de um terminal (o primeiro comando lista os emuladores e seus IDs): 
      1
2
      flutter emulators
flutter emulators --launch <id>

    1. Aguarde até que a tela de boas-vindas do [Android] apareça na janela do emulador: a primeira inicialização pode levar vários minutos. Depois, verifique se o [Flutter] reconhece o emulador, que deve aparecer na lista (por exemplo, [emulator-5554], plataforma [android-x64]): 
    flutter devices

Tente o seguinte, nesta ordem: (1) aguarde a tela de boas-vindas aparecer e execute o comando novamente; (2) reinicie o [adb] com os três comandos a seguir (no [Windows], dentro do [PowerShell]), de modo que o último exiba “device” em vez de “offline”; (3) no [Device Manager], no menu [⋮] do dispositivo, selecione [Cold Boot Now] ou, em último caso, [Wipe Data].

    flutter run -d emulator-5554

    2.1.4. Preparação do celular Android

    Para executar a aplicação em um celular [Android] real, o celular precisa ser configurado para permitir o controle a partir do computador:

    1. Ative as opções do desenvolvedor: abra [Settings / About phone] e toque em [Build number] várias vezes (geralmente 7) até que o celular indique que você é um desenvolvedor. Os nomes exatos variam conforme o fabricante.
    2. Ative a [USB debugging] no menu [Developer options] (adicionado na etapa anterior).
    3. Conecte o celular ao computador com um cabo USB que transfira dados (e não apenas carregue o aparelho) e aceite o pedido de permissão de depuração USB no celular. No Windows, se o celular não for reconhecido, instale o driver USB do fabricante (“OEM USB drivers”, veja [https://developer.android.com/studio/run/oem-usb]).
    4. Verifique se o [Flutter] detecta o celular: ele deve aparecer na lista exibida pelo comando a seguir, junto com a plataforma [android]: 
      4
      flutter devices

    O celular acessará o servidor [NestJS] pelo endereço IP do computador na rede local (e não por [localhost]): essa configuração é descrita no Capítulo 5.
